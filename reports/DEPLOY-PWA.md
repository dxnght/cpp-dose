# Розгортання PWA — крок за кроком

*2026-07-24. Мета: дати медикам робоче посилання на застосунок **цього тижня**,
не чекаючи ні Google Play (де мінімум 2 тижні закритого тестування), ні App
Store (де ще треба оновити macOS і Xcode).*

**Добра новина:** PWA вже налаштований у `vite.config.ts` — маніфест, іконки,
service worker з precache усього застосунку і **без жодного runtime-кешування**
(бо мережі під час роботи немає взагалі, Art. V). Нічого програмувати не треба,
лишилось тільки розмістити статику.

---

## Що це дає і чого не дає — чесно

**Дає:**
- Робоче посилання: медик відкриває → «Додати на головний екран» → іконка як у
  звичайного застосунку, працює **повністю офлайн** після першого відкриття.
- Нуль оплат, нуль рев'ю, нуль очікування. Оновлення — миттєві.
- Спосіб **перевірити iOS уже зараз**, не оновлюючи macOS і не чекаючи Xcode 26.
- Публічний URL, який заодно закриває вимогу Google Play про політику
  приватності.

**Не дає:**
- **Будильник при закритому застосунку.** У PWA немає ні OS-нотифікацій через
  AlarmManager, ні надійних фонових таймерів — особливо на iOS. Працює, поки
  застосунок відкритий і екран увімкнений.
- Автозапуску, повного контролю над екраном, гарантії, що iOS не вивантажить
  вкладку з памʼяті.

➡️ **Тому в описі посилання це треба сказати прямо.** Готовий текст — у кроці 6.
Це той самий fail-closed принцип: краще чесно попередити, ніж дати медику
хибну впевненість.

## Крок 1 — зібрати PWA-версію

```bash
cd ~/docs/work/2026dev/cpp-dose
git checkout fix/ux-review-findings
npm ci
VITE_VARIANT=play npm run build
```

Чому `VITE_VARIANT=play`: у PWA підсистема OS-нотифікацій усе одно не працює,
а цей прапорець вимикає її й показує **чесний банер** «будильник працює, поки
застосунок відкритий» замість поради про оптимізацію батареї, яка тут
безглузда.

Результат — папка `dist/`. Перевір, що всередині є `index.html`,
`manifest.webmanifest`, `sw.js` та іконки.

```bash
ls dist/ | head -20
```

Локальна перевірка перед публікацією:

```bash
npm run preview
```

Відкрий у браузері, вимкни мережу (DevTools → Network → Offline), перезавантаж
— застосунок має працювати.

## Крок 2 — обрати хостинг

Потрібна лише статика + HTTPS (обовʼязково: без HTTPS service worker не
працює). Усі варіанти нижче безкоштовні й достатні.

| Варіант | Плюси | Мінуси |
|---|---|---|
| **Cloudflare Pages** ⭐ | Безкоштовно, швидко в Україні, свій домен, простий деплой із папки | Треба акаунт Cloudflare |
| **Netlify** | Найпростіший — можна просто перетягнути папку `dist/` мишкою | Безкоштовний ліміт трафіку |
| **GitHub Pages** | Уже є репозиторій | Потрібен публічний репозиторій **або** платний план; код зараз закритий |
| **Власний VPS + nginx** | Повний контроль | Треба адмініструвати, сертифікат, оновлення |

**Рекомендую Cloudflare Pages.** Якщо хочеться зробити це за 5 хвилин прямо
зараз — Netlify Drop (крок 3б).

---

## Крок 3а — Cloudflare Pages (рекомендований шлях)

1. Зареєструйся на `dash.cloudflare.com` (безкоштовно).
2. **Workers & Pages → Create → Pages → Upload assets.**
3. Назва проєкту: `cpp-dose`.
4. Перетягни вміст папки `dist/` (саме **вміст**, не саму папку).
5. **Deploy.**

Отримаєш адресу на кшталт `https://cpp-dose.pages.dev`.

**Оновлення надалі:** той самий екран → Create new deployment → перетягнути
новий `dist/`. Або підключити git-репозиторій для автодеплою (Build command:
`npm run build`, Build output: `dist`, змінна оточення `VITE_VARIANT=play`).

---

## Крок 3б — Netlify Drop (найшвидший, 2 хвилини)

1. Відкрий `app.netlify.com/drop`.
2. Перетягни папку `dist/` у вікно браузера.
3. Готово — отримаєш посилання одразу, навіть без реєстрації (але
   зареєструйся, щоб посилання не зникло і щоб можна було оновлювати).

Це найшвидший спосіб отримати щось, що можна відразу дати медику на тест.

---

## Крок 4 — свій домен (опційно, але варто)

`cpp-dose.pages.dev` виглядає технічно. Для листів у фонди краще щось на
кшталт `cpp-dose.org` або `.com.ua`.

1. Купити домен (реєстратор на вибір; `.com.ua` дешевий).
2. Cloudflare Pages → Custom domains → Set up a domain → вписати домен.
3. Прописати DNS-записи, які покаже Cloudflare.
4. HTTPS-сертифікат випуститься автоматично.

## Крок 5 — політика приватності (потрібна і для Play)

Google Play вимагає **публічний URL, не PDF**. Оскільки хостинг уже є,
розмісти файл поруч: `dist/privacy.html` → буде доступний за
`https://<домен>/privacy.html`.

Текст буде коротким, бо застосунок реально нічого не збирає:

> **Політика приватності CPP-DOSE**
>
> CPP-DOSE не збирає, не зберігає на серверах і не передає жодних даних.
> Застосунок працює повністю на пристрої й не здійснює мережевих запитів під
> час роботи. Немає акаунтів, реєстрації, аналітики й телеметрії.
>
> Дані, які ви вводите (вага пацієнта, параметри крапельниці, необовʼязкова
> мітка дріпу), зберігаються лише в памʼяті пристрою й ніколи не залишають
> його. Мітка дріпу не записується у постійне сховище взагалі.
>
> Застосунок є довідковим інструментом підтримки рішень і не замінює
> протоколи, медичне керівництво чи клінічне судження.
>
> Контакт: [твоя пошта]
> Оновлено: [дата]

⚠️ Це чернетка на основі того, що я перевірив у коді. Перед публікацією
перечитай сам — за неї відповідаєш ти, не я.

## Крок 6 — текст для роздачі медикам

Разом із посиланням давай це (інакше будуть очікувати будильник у фоні):

> **CPP-DOSE — офлайн калькулятор крапельниць і дозування**
> 🔗 [посилання]
>
> **Як встановити:**
> • Android (Chrome): відкрити посилання → меню ⋮ → «Встановити застосунок»
> • iPhone (Safari): відкрити → кнопка «Поділитися» → «На екран Home»
>
> Після першого відкриття працює **повністю без інтернету**.
>
> ⚠️ **Важливо про будильник:** у цій (веб) версії сигнал про закінчення
> мішка працює, **поки застосунок відкритий і екран увімкнений**. Якщо
> потрібен будильник із заблокованим екраном — напиши, надішлю APK-версію
> для Android.
>
> Зворотний звʼязок вітається — що незручно, що не працює, чого бракує.
